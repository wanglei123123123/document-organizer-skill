# 测试用例脑图输出格式（Mindmap Format）

> 本文定义测试用例的**脑图结构化输出格式**，与 `testcase-template.md` 的 Markdown 格式并列，适用于：
> - XMind / MindMaster / 幕布 等脑图工具直接导入
> - Markdown 大纲 (`#` / `-`) 嵌入文档
> - Mermaid mindmap 嵌入在线预览
> - 需求评审/用例评审的树状可视化

---

## 一、脑图节点规范

### 1.1 节点层级模型

```
根节点：需求名称（Requirement）
 └── F 场景（Feature/Scenario Group）
      └── S 用例标题（Case）
           ├── [label] 优先级（P0/P1/P2）
           ├── [label] 所属端（Android / iOS / PC / H5）
           ├── G 操作前提（Given）         ← 可选，没有 G 时跳过
           │    └── W 操作步骤（When）      ← ⚠️ 一个 S 下仅有一个 W
           │         └── T 预期结果（Then）
           └── W 操作步骤（When）           ← 当没有 G 时，S 直接挂 W（同样只有一个）
                └── T 预期结果（Then）
```

> ⚠️ **一个 S 必须只有一个 W** — 若一条用例存在多个操作步骤，应合并为一段 W 文案；
> 若这些步骤属于不同的测试目的/验证点，应**拆分为多条独立的 S**（符合用例原子性原则 DRY，
> 参见 `testcase-template.md` 3.1 原则一）。

### 1.2 节点字段定义

| 节点 | 前缀/含义 | 必填 | 说明 |
|------|----------|------|------|
| **根** | 需求名称 | ✅ | 例："积分中心签到翻倍卡" |
| **F** | 场景分组（Feature） | ✅ | 一个业务场景下的多条用例聚合，如"签到领奖"、"翻倍卡使用"、"异常流" |
| **S** | 用例标题（Scenario） | ✅ | 简短描述该用例测什么，对应规范里的 Scenario 场景命名 |
| **label** | 优先级 + 所属端 | ✅ | 与 S 并行展示（脑图节点自带标签位），不作为子节点 |
| **G** | 操作前提（Given） | ⭕ 可选 | 没有 G 时该层跳过，W 直接挂 S |
| **W** | 操作步骤（When） | ✅ | **一个 S 下仅 1 个 W**，多步骤合并为一段文案（分号/编号内联）；多个验证点应拆分为多条 S |
| **T** | 预期结果（Then） | ✅ | 每个 W 下可有多个 T 断言（建议 1~3 个，超 3 个考虑拆 S） |

### 1.3 核心规则

| # | 规则 | 说明 |
|---|------|------|
| **R-1** | **优先级 + 所属端必须用 label**，不作为子节点 | 脑图工具支持 "节点+标签" 并列展示 |
| **R-2** | **G 可选**，没有 G 时直接 S → W | 简化层级 |
| **R-3** | **一个 S 下仅有 1 个 W** ⚠️ | 多步骤合并为一段 W 文案（分号/编号内联）；不同测试目的须拆分为多条 S |
| **R-4** | **一个 W 可以有多个 T**，每个 T 一个断言 | 避免 Then 堆多检查点 |
| **R-5** | S 节点文案仅"标题+简述"，不含操作细节 | 操作放在 W，预期放在 T |
| **R-6** | F 节点下用例顺序：先正向 → 再备选 → 再异常 | 阅读友好 |
| **R-7** | 同一 F 下多个 S 之间独立，不相互依赖 | 符合用例独立原则 |
| **R-8** | G / W / T 保留原用例规范要求（如 G/W 不含"或/分别"） | 复用 `testcase-template.md` |

## 二、三种脑图输出格式

### 2.1 Markdown 大纲（首选，可导入 XMind / 幕布 / MindMaster）

> XMind 8/2024、MindMaster、WorkFlowy、幕布、Logseq 均直接支持 Markdown 大纲导入。
>
> **注**：下方示例为通用多端演示（Android/iOS/H5）。
> **PCYYB 项目**必须使用 `testcase-labels.md` 规定的标签字典：
> `[优先级] [所属端] [适用阶段] [所属测试方]? [自动化]?`
> 例如：`### S：启动应用宝显示首页 [P0] [PCYYB,ARM] [冒烟,集成]`

```markdown
# 需求名称：积分中心签到翻倍卡

## F：签到领奖

### S：连续签到7天领取翻倍卡 [P0] [Android/iOS/H5]
- G：使用QQ账号登录，进入积分中心签到页，已连续签到6天
  - W：第7天 0:01 点击"签到"按钮
    - T：签到成功，+10 积分
    - T：弹出"翻倍卡已发放"Toast
    - T：翻倍卡列表新增1张，有效期24小时

### S：连续签到未满7天不发翻倍卡 [P1] [Android/iOS/H5]
- G：使用QQ账号登录，已连续签到5天
  - W：第6天点击"签到"按钮
    - T：签到成功
    - T：不发放翻倍卡

### S：签到按钮无障碍焦点正确 [P2] [H5]
- W：键盘 Tab 键聚焦到签到按钮
  - T：按钮出现可见焦点环
  - T：朗读器播报"签到，按钮"

## F：翻倍卡使用

### S：有效期内使用翻倍卡 [P0] [Android/iOS]
- G：账号持有1张有效期内翻倍卡，进入任务中心
  - W：点击"完成任务"并在结果页勾选"使用翻倍卡"
    - T：奖励积分显示为 2 倍
    - T：翻倍卡使用次数 -1

### S：翻倍卡过期自动清理 [P1] [Android/iOS]
- G：账号持有1张已过期翻倍卡
  - W：重新打开签到页
    - T：过期翻倍卡从列表移除
    - T：个人中心"翻倍卡数量"同步更新

## F：异常场景

### S：弱网下签到请求超时 [P0] [Android/iOS]
- G：账号已登录，进入签到页，网络为 2G 弱网
  - W：点击"签到"按钮等待超时
    - T：显示"网络异常，请重试"
    - T：不扣除签到次数（幂等）

### S：断网点击签到 [P1] [Android/iOS]
- W：设备完全断网，点击"签到"按钮
  - T：显示"网络异常"
  - T：不弹假成功
```

**特点**：
- 层级：`#` 根 → `##` F → `###` S → `-` G → `  - W` → `    - T`
- label 用 `[P0] [Android/iOS]` 形式挂在 S 标题末尾，导入 XMind 后自动识别为标签
- 没有 G 时省略 `- G`，W 直接作为 S 的子节点（用 `- W：...`）

### 2.2 Mermaid Mindmap（嵌入 Markdown/在线渲染）

> 适合嵌入 README / Confluence / Notion / GitLab Wiki。

```
mindmap
  root((积分中心签到翻倍卡))
    签到领奖 F
      ::icon(fa fa-star)
      连续签到7天领取翻倍卡 S
        P0, Android/iOS/H5
        Given
          已连续签到6天
        When 第7天 0:01 点击签到
          Then 签到成功+10积分
          Then 翻倍卡已发放
          Then 翻倍卡有效期24小时
      连续签到未满7天不发卡 S
        P1, Android/iOS/H5
        Given 已连续签到5天
        When 第6天点击签到
          Then 不发放翻倍卡
    翻倍卡使用 F
      有效期内使用翻倍卡 S
        P0, Android/iOS
        Given 持有1张有效卡
        When 勾选使用翻倍卡
          Then 积分翻倍
          Then 卡使用次数-1
    异常场景 F
      弱网下签到超时 S
        P0, Android/iOS
        Given 2G弱网
        When 点击签到等待超时
          Then 显示网络异常
          Then 签到次数不扣（幂等）
```

**注意**：Mermaid 不支持真正的"并行 label"，将优先级和所属端用次级文本行表达。

### 2.3 FreeMind / XMind XML（批量生成导入）

> 适合程序化大批量生成后直接导入 XMind / FreeMind / MindManager。

```xml
<map version="1.0.1">
  <node TEXT="积分中心签到翻倍卡">
    <node TEXT="F：签到领奖">
      <node TEXT="S：连续签到7天领取翻倍卡">
        <attribute NAME="优先级" VALUE="P0"/>
        <attribute NAME="所属端" VALUE="Android/iOS/H5"/>
        <node TEXT="G：已连续签到6天">
          <node TEXT="W：第7天 0:01 点击签到">
            <node TEXT="T：签到成功+10积分"/>
            <node TEXT="T：翻倍卡已发放"/>
            <node TEXT="T：翻倍卡有效期24小时"/>
          </node>
        </node>
      </node>
    </node>
  </map>
</map>
```

**特点**：`<attribute>` 节点作为 label 与 S 并列展示，XMind 导入后会显示为节点旁的标签徽章。

## 三、label 规范

> 完整规范（含字典、组合规则、过滤规则）详见 `testcase-labels.md`。
> 脑图 label 展示顺序固定为：
> `[优先级] [所属端] [适用阶段] [所属测试方]? [自动化]?`

### 3.1 优先级 label（必填）

| 取值 | 使用场景 |
|------|----------|
| `P0` | 核心必测（需求明确功能点 / 主流程 / 核心交叉场景 / UI 不错乱） |
| `P1` | 功能完整覆盖（延伸功能 / 非主路径 / UI体验 / 不同版本） |
| `P2` | 异常与边界（异常场景 / 特殊场景 / 文案） |

### 3.2 所属端 label（必填）

| 取值 | 说明 |
|------|------|
| `PCYYB` | PC 应用宝主产品（x86） |
| `ARM` | 应用宝 ARM 架构版 |
| `手助` | 手机助手 |
| `微软绿色版` | 微软绿色包（x86） |
| `ARM微软绿色版` | 微软绿色包（ARM） |
| `360SDK` | 360 SDK 集成版 |
| `联想SDK` | 联想 SDK 集成版 |
| 多端 | 多值用英文逗号分隔，如 `[PCYYB,ARM,手助]` |

### 3.3 适用阶段 label（必填）

| 取值 | 说明 |
|------|------|
| `冒烟` | 最核心流程，上线必过 |
| `集成` | 集成测试（包含冒烟） |
| `虎牙集成` | 虎牙侧负责的集成 |
| `微软集成用例` / `360集成用例` / `联想集成用例` | SDK 渠道专属集成 |
| `增量` | 随需求变更的增量用例 |
| `待审核` | 新编写未评审 ⚠️ 评审前必须存在 |

### 3.4 所属测试方 label（选填）

| 取值 | 说明 |
|------|------|
| （省略） | 腾讯侧负责的用例 |
| `虎牙侧` | 虎牙侧负责执行并维护 |

### 3.5 自动化 label（预留）

| 取值 | 说明 |
|------|------|
| （省略） | 未自动化 |
| `待自动化` | 准备实现 |
| `已自动化` | 已实现+已配置+可替代手工 |
| `已自动化但暂未配置` | 已实现但未配置流水线，不能替代手工 |

### 3.6 label 并行展示的三种写法

```
✅ Markdown：用 [方括号] 挂在 S 标题末尾（顺序固定）
   ### S：连续签到7天领取翻倍卡 [P0] [PCYYB,ARM] [集成,冒烟]
   ### S：虎牙侧下载用例 [P1] [PCYYB] [虎牙集成] [虎牙侧]
   ### S：已自动化的登录用例 [P0] [PCYYB,手助] [冒烟,集成] [已自动化]

✅ XMind XML：用 <attribute> 子元素
   <node TEXT="S：..."><attribute NAME="优先级" VALUE="P0"/>
     <attribute NAME="所属端" VALUE="PCYYB,ARM"/>
     <attribute NAME="适用阶段" VALUE="冒烟,集成"/>
   </node>

✅ 脑图工具：节点上的 "标签/Label" 字段（XMind 用 Shift+F3）
   节点标题 + 右上角徽章 [P0] [PCYYB,ARM] [冒烟,集成]
```
   节点标题 + 右上角徽章 [P0] [Android/iOS]
```

## 四、输出原则

### 4.1 层级判断流程

```
对每条测试用例：
  ┌─────────────────────────────┐
  │ 1. 是否有 Given 前提条件？    │
  └──────┬──────────────────┬──┘
         │Yes                │No
         ▼                   ▼
  S → G → W → T         S → W → T
  （四层）               （三层）
```

### 4.2 多 G / 多 W / 多 T 处理

| 场景 | 处理方式 |
|------|----------|
| 一条用例有多个 Given | 多个 G 作为 S 的平级子节点（`- G：...`），或合并为一行（分号分隔） |
| **一条用例有多个操作步骤（When）** | **⚠️ 必须合并为 1 个 W 文案**，步骤内联编号：`W：1)点击A 2)输入B 3)点击C`<br/>若多个步骤属于不同测试目的 → **拆分为多条 S**（原子性原则） |
| 一条 When 有多个 Then 断言 | 每个 T 作为 W 的子节点（一条 W 可挂 N 个 T，建议 1~3 个） |

#### 多步骤合并示例

```
❌ Bad（一个 S 下多个 W）:
  ### S：输入关键词搜索应用 [P0]
  - G：已登录，在首页
    - W1：点击搜索框
      - T：获得焦点
    - W2：输入"王者荣耀"
      - T：文本正确显示
    - W3：按回车
      - T：展示结果

✅ Good 方案一（合并为 1 个 W，内联编号）:
  ### S：输入关键词搜索应用 [P0]
  - G：已登录，在首页
    - W：1)点击搜索框；2)输入"王者荣耀"；3)按回车
      - T：搜索框获得焦点，文本正确显示
      - T：搜索结果页展示"王者荣耀"相关应用

✅ Good 方案二（拆分为多条 S，针对性更强）:
  ### S：搜索框获得焦点展示历史/热搜 [P1]
  - G：已登录，在首页
    - W：点击搜索框
      - T：输入框获得焦点，展示搜索历史与热搜

  ### S：输入关键词完成搜索 [P0]
  - G：已登录，搜索框处于聚焦态
    - W：输入"王者荣耀"并按回车
      - T：搜索结果页展示"王者荣耀"相关应用
```

**选择建议**：
- 步骤仅为达成同一目标的**过程操作**（点击→输入→提交） → **方案一（合并 W）**
- 每个步骤都有**独立验证点**（焦点态/文本态/结果态各自重要） → **方案二（拆分 S）**

### 4.3 S 节点简述规范

S 是用例标题 = 测试场景，**仅描述"测什么"**：

```
✅ Good:
  S：连续签到7天领取翻倍卡
  S：弱网下签到请求超时处理
  S：翻倍卡过期自动清理

❌ Bad:
  S：测试签到                       ← 太模糊
  S：点击签到按钮后弹出翻倍卡       ← 混入操作细节（应在 W 里）
  S：签到 + 领奖 + 使用翻倍卡       ← 多验证点（应拆分）
```

### 4.4 导入 XMind 的实操步骤

```
方式 A：Markdown 导入
  1. 把脑图内容保存为 .md 文件
  2. XMind 打开 → 文件 → 导入 → Markdown
  3. label `[P0] [Android]` 自动识别为节点标签

方式 B：复制粘贴
  1. 复制 Markdown 大纲文本
  2. XMind 空白画布按 Ctrl+V 直接粘贴
  3. 自动生成层级结构

方式 C：XMind XML 导入
  1. 程序化生成 XML 文件
  2. 改扩展名为 .xmind.zip 或 .mm
  3. XMind → 导入 → FreeMind / MindManager
```

## 五、完整示例（多端用例脑图）

### 需求："应用宝下载应用并展示进度"

```markdown
# 应用宝下载应用并展示进度

## F：下载启动

### S：已登录用户点击下载启动任务 [P0] [Android/iOS/PC]
- G：已使用QQ登录应用宝，网络正常，应用未下载过
  - W：点击"王者荣耀"卡片的"下载"按钮
    - T：按钮变为进度条
    - T：首页、我的、下载盒子三处同步显示进度

### S：未登录用户点击下载触发登录引导 [P0] [Android/iOS/PC]
- G：应用宝处于游客态（未登录），网络正常
  - W：点击"王者荣耀"卡片的"下载"按钮
    - T：弹出"登录后下载"引导弹窗

## F：下载过程

### S：下载中点击暂停 [P0] [Android/iOS/PC]
- G：已触发"王者荣耀"下载，当前进度 30%
  - W：点击卡片上的"暂停"图标
    - T：按钮变为"继续"
    - T：进度条停留在 30%
    - T：下载盒子状态同步为"已暂停"

### S：已暂停后点击继续（断点续传）[P0] [Android/iOS/PC]
- G：账号已登录，"王者荣耀"处于已暂停状态，进度 30%
  - W：点击卡片上的"继续"图标
    - T：从 30% 继续，不重新下载
    - T：下载盒子状态同步为"下载中"

### S：下载中切换账号（QQ→微信）[P0] [Android/iOS]
- G："王者荣耀"下载进度 50%，当前QQ登录
  - W：从"我的"页切换为微信账号登录
    - T：原下载任务暂停并归属原QQ账号
    - T：新账号下载列表为空，不串数据

## F：异常场景

### S：下载中断网 [P0] [Android/iOS/PC]
- G："王者荣耀"下载进度 40%
  - W：关闭Wi-Fi和数据（断网）
    - T：自动暂停，按钮变为"继续"
    - T：Toast 提示"网络异常，已自动暂停"

### S：磁盘空间不足时启动下载 [P0] [PC]
- G：C盘剩余空间 < 应用安装包大小
  - W：点击"下载"按钮
    - T：预检失败，不进入下载状态
    - T：弹出"空间不足，请清理"提示

### S：快速连续点击下载按钮 [P2] [Android/iOS/PC]
- W：1秒内连续点击"下载"按钮 5 次
  - T：仅触发1次下载任务（防抖/幂等）
  - T：不出现重复下载
```

## 六、Checklist（生成脑图前自检）

### 结构完整性
- [ ] 根节点是需求名称（不含操作/版本号）？
- [ ] 每条用例是否至少有 1 个 F 归属？
- [ ] 每条 S 是否有 P0/P1/P2 优先级 label？
- [ ] 每条 S 是否有所属端 label？
- [ ] 每条 S 是否至少有 1 个 W？
- [ ] 每个 W 是否至少有 1 个 T？

### 内容规范（复用 `testcase-template.md`）
- [ ] S 标题清晰，不含"或/分别/任意"选择性词语？
- [ ] S 标题不以操作动词起头？
- [ ] G 不依赖其他用例（无 TC-xxx 引用）？
- [ ] W 为动宾结构，无连词/假设词/预期混入？
- [ ] T 无操作步骤、无假设词、无"支持/可以"等概括词？

### 脑图专属
- [ ] 没有 G 时 W 是否直接挂 S（不留空 G 节点）？
- [ ] **一个 S 下是否仅有 1 个 W**？多步骤合并或拆分为多条 S？
- [ ] 多个 T 是否拆为多个 T 节点（而不是一条 T 堆多个断言）？
- [ ] label（优先级+端）是否并行展示，不作为子节点？
- [ ] F 下用例顺序：正向→备选→异常 ？
