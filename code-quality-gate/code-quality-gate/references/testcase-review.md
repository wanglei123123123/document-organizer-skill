# 用例评审方法论（Test Case Review）

> 对已编写的测试用例集进行**规范性+完整性+耦合场景**三维评审，产出「用例缺失场景 + 用例不规范点」清单。
> 评审依据：
> - 规范层：`testcase-template.md`（G/W/T 规则 + 优先级 + 标签）
> - 方法论层：`test-methods.md`（边界值/等价类/因果图/正交/错误推测）
> - 耦合层：`pcyyb-checklist.md` + `test-strategy.md`（影响面/弱网/兼容性/历史版本）
> - 缺陷层：`defect-analysis.md`（典型缺陷模式）

## 二、维度一：规范性检查（基于用例规范+标签规范）

### 2.1 元数据/标签类规则（FORM-META）

| 规则ID | 检查项 | 严重度 | 依据 |
|--------|--------|--------|------|
| **FORM-M01** | 用例必须包含编号 `TC-{模块}-{编号}` | BLOCKER | 5.1 单条用例格式 |
| **FORM-M02** | 用例必须包含测试场景标题 | BLOCKER | 1.2 五大元素 |
| **FORM-M03** | 用例必须包含优先级（P0/P1/P2） | BLOCKER | 4.1 优先级定义 |
| **FORM-M04** | 用例必须包含所属模块 | CRITICAL | 5.1 格式 |
| **FORM-M05** | 用例必须包含测试方法（边界/等价/错误推测…） | CRITICAL | 5.1 格式 |
| **FORM-M06** | 用例必须包含 Given / When / Then 三要素 | BLOCKER | 1.2 五大元素 |
| **FORM-M07** | 优先级取值仅允许 P0/P1/P2 | MAJOR | 4.1 定义 |
| **FORM-M08** | 用例集必须包含「用例覆盖矩阵」 | MAJOR | 5.2 用例集格式 |

### 2.2 标题/命名类规则（FORM-TITLE）

| 规则ID | 检查项 | 触发词/特征 | 严重度 |
|--------|--------|-------------|--------|
| **FORM-T01** | 标题不得含操作动词起头（"点击""输入"） | `^点击│^输入│^选择│^打开` | CRITICAL |
| **FORM-T02** | 标题不得过于模糊 | 长度<6 或含"测试"二字的通用描述 | MAJOR |
| **FORM-T03** | 标题不得含 "bug验证"/"验证bug"/"fix" | 含这些关键词 | MAJOR |
| **FORM-T04** | 多场景/多页面时标题须含"-场景名/页面名" | Given/When 含多页面特征但标题无-分隔 | CRITICAL |

### 2.3 前置条件 Given 规则（FORM-G）

| **FORM-G05** | ❌ Given 不得含假设词 | `可能│也许│大概` | CRITICAL | - |

| 规则ID | 检查项 | 触发词/特征 | 严重度 | 依据 |

### 2.6 原子性/正交性规则（FORM-ATOM）

| 规则ID | 检查项 | 触发特征 | 严重度 |
|--------|--------|----------|--------|
| **FORM-A01** | ❌ 用例原子性：一条用例≤1 个验证点 | Then 含多个动词/检查点(≥3个) | CRITICAL |
| **FORM-A02** | ❌ DRY：无重复验证同一功能 | 两条用例的 Given/When/Then 相似度 >85% | MAJOR |
| **FORM-A03** | ⚠️ 可判定性：Given/When 避免"任意""适当" | 含 `任意│合适的│适当的│若干` | MAJOR |

### 2.7 优先级分布规则（FORM-PRI）

|--------|--------|----------|--------|

| **FORM-P04** | 安全/支付/账号类必须至少 1 条 P0 | 模块涉及安全但无 P0 用例 | CRITICAL |

## 三、维度二：完整性检查（基于用例设计方法）

> 对每个功能点/模块，按五大测试方法逐一检查是否覆盖。缺失即计为「缺失场景」。

### 3.1 场景法覆盖（COV-SCN）

> 详细方法论参见 `case-design-methods.md` 第三章「场景法」。
> 核心：基本流（Basic Flow）+ 备选流（Alternate Flow）+ 数据驱动。

| 规则ID | 检查项 | 触发缺失的特征 | 严重度 |
|--------|--------|----------------|--------|
| **COV-S01** | 主成功场景必须覆盖 | 模块无 P0 正向用例 | BLOCKER |
| **COV-S02** | 分支成功场景必须覆盖 | 用例只有主流程，无分支路径 | CRITICAL |
| **COV-S03** | 分支失败场景必须覆盖 | 无异常/失败分支用例 | CRITICAL |
| **COV-S04** | 用户路径完整闭环 | 缺"返回""取消""关闭""重试"路径 | MAJOR |
| **COV-S05** | **场景五要素完整** | 缺 Actor/Goal/Precondition/Basic Flow/Postcondition | CRITICAL |
| **COV-S06** | **基本流显式标注** | 场景用例中未标识 "基本流/Basic Flow" | MAJOR |
| **COV-S07** | **备选流 A（成功替代）覆盖** | 不同方式达成同一目标的路径未覆盖 | MAJOR |
| **COV-S08** | **备选流 B（失败可恢复）覆盖** | 错误→重试的可恢复路径未覆盖 | CRITICAL |
| **COV-S09** | **备选流 C（失败终止）覆盖** | 致命错误终止路径未覆盖 | MAJOR |
| **COV-S10** | **备选流 D（并行打断）覆盖** | 场景中被外部打断的路径未覆盖（切账号/来电/通知） | MAJOR |
| **COV-S11** | **数据驱动表** | 多角色/多数据场景未使用数据驱动表，而是堆在一条用例 | MAJOR |
| **COV-S12** | **多通道覆盖** | UX-5 多入口未覆盖（首页/搜索/分享/扫码/深链） | MAJOR |
| **COV-S13** | **真实数据来源** | 数据集全部编造（如 `abc/test`），未来自线上真实分布 | MINOR |

## 五、评审执行流程

### 5.1 输入

```yaml
# 评审输入
testcases: "path/to/testcases.md"       # 被评审的用例集（Markdown）
requirement: "path/to/req.yaml"          # 可选：需求文档

  module: "应用宝-下载"                   # 模块名
  platforms: ["PC"]                      # 平台
  involves: ["download", "login"]        # 涉及耦合场景
```

### 5.2 执行步骤

```
1. 解析用例集 → 提取每条用例的 ID / 标题 / 优先级 / G / W / T
2. 维度一规范性扫描 → 对每条用例跑 FORM-* 规则 → 生成「不规范点」
3. 维度二完整性扫描 → 对用例集整体跑 COV-* 规则 → 生成「缺失场景」
4. 维度三耦合扫描 → 结合模块类型跑 COUP-* 规则 → 生成「缺失场景」
5. 聚合输出 → 两份表格 + JSON 结构化数据
```

## 六、评审 Checklist（AI/人工通用）

### 规范性自检
- [ ] 每条用例是否包含编号/标题/优先级/模块/方法/GWT 六要素？
- [ ] **标签完整**：优先级+所属端+适用阶段 是否必填且取值合法（详见 `testcase-labels.md`）？
- [ ] **冒烟用例**是否同时标了"集成"？**虎牙侧**用例是否标了"虎牙集成"？
- [ ] **新编写用例**评审前是否带"待审核"标签？
- [ ] 标题是否描述场景而非操作？是否含"-场景/页面名"区分？
- [ ] Given 是否独立、完整、无选择性词语？
- [ ] When 是否动宾结构、无"或/分别"、无假设词、无预期混入？
- [ ] Then 是否无操作、无说明词、无概括词、一条一个检查点？
- [ ] 优先级分布是否合理（P0 10-30% / P1 ≥50% / P2 ≥10%）？
- [ ] 兼容性用例是否整合为1条+环境矩阵？

### 完整性自检
- [ ] **场景法**：是否识别 Actor/Goal/基本流？是否穷举 A/B/C/D 四类备选流？是否使用数据驱动表？是否覆盖多通道入口？
- [ ] 边界值：空/最小/最大/超限是否覆盖？
- [ ] 等价类：用户分群/登录态/APK类型/安装状态/多语言是否覆盖？
- [ ] **判定表**：多条件决策的业务是否建立判定表？化简后每条规则是否 1 条用例？
- [ ] **状态转换**：流程性业务是否建立状态机？L0全状态 + L1全转换（含非法事件）+ L3全有效路径 + L4循环路径是否 100% 覆盖？
- [ ] 错误推测：空值/并发/切换/杀进程/权限拒绝是否覆盖？
- [ ] 正交实验：兼容性矩阵维度是否充分？
- [ ] **存储（D9）**：磁盘满/权限拒绝/路径异常/写入中断/卸载清理 是否覆盖？

### 耦合场景自检
- [ ] 下载类：状态机/跨页面一致性/切账号/断网/**磁盘满/权限撤销** 是否覆盖？
- [ ] 登录类：QQ/微信切换/游客转正/退出/Token 是否覆盖？
- [ ] 窗口类：拖拽/多屏/大小调整 是否覆盖？
- [ ] 网络类：弱网/断网/切网/超时 是否覆盖？
- [ ] 兼容类：OS/安装版本/引擎/硬件 是否覆盖？
- [ ] 频控类：次数上限/时间窗 是否覆盖？
- [ ] **存储类**：空间/权限/路径/完整性/卸载清理/升级迁移/并发写 是否覆盖？
