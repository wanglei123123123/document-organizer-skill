# 图片原型质量检测规则库 (Image/Prototype Scan Rules)

> 本文件定义针对**图片格式的需求文档/UI设计稿**（PNG/JPG/SVG/Sketch导出等）的质量检测规则。
> 结合AI视觉分析能力，将测试方法论映射到UI/UX层面的检测项。
> 使用方式：通过 `read_file` 工具读取图片后，AI按本规则逐项检查。

## 详细规则定义与视觉检查指南

### IMG-COMP 组 — 原型完整性

#### IMG-COMP-01: 核心页面/视图缺失
```yaml
规则ID: IMG-COMP-01
名称: "核心业务页面或关键视图在设计稿中缺失"
方法来源: 因果图法
严重程度: BLOCKER
检测方式: AI视觉分析 + 清单核对

检查方法:
  1. 先从需求文档提取"页面清单"(应有N个页面)
  2. 与设计稿图片中的实际页面进行比对
  3. 找出缺失的页面

  核心页面类别 (根据产品类型选择):
  ┌─────────────────────────────────────────────┐
  │ 通用必备页面                                  │
  ├── 首页/仪表盘 (Dashboard/Home)               │
  ├── 列表页 (List/Search Result)                │
  ├── 详情页 (Detail)                            │
  ├── 表单页 (Form/Create/Edit)                  │
  └── 用户相关 (Login/Register/Profile)          │
  │                                              │
  │ 电商类额外: 购物车/结算/支付结果/订单详情     │
  │ 社交类额外: 消息/个人主页/设置               │
  │ 管理后台额外: 权限管理/操作日志/系统配置      │
  └─────────────────────────────────────────────┘

  AI视觉检查步骤:
  Step 1: 识别每张设计稿截图的页面标题/类型
  Step 2: 汇总已有页面列表
  Step 3: 对照需求中的页面清单,标记缺失项
  Step 4: 对缺失页面输出 BLOCKER 问题

  示例输出:
  ❌ [BLOCKER] 缺失页面: "订单支付结果页(成功/失败)"
     → 需求文档 US-023 定义了支付成功/失败两种结果态,
       但设计稿中没有对应的设计
```

#### IMG-COMP-02: 关键状态(空/加载/错误)设计缺失
```yaml
规则ID: IMG-COMP-02
名称: "关键页面的空状态、加载态、错误态设计稿缺失"
方法来源: 边界值分析法
严重程度: CRITICAL

检查方法:
  对每个核心页面,检查以下状态是否都有设计:

  必须有设计的边界状态:
  ┌────────────┬──────────────────────────────────┐
  │ 状态类型   │ 触发场景                          │
  ├────────────┼──────────────────────────────────┤
  │ 空状态     │ 首次使用 / 数据被清空 / 无结果    │
  │ 加载中     │ 首次进入 / 下拉刷新 / 提交等待    │
  │ 加载失败   │ 网络错误 / 服务端异常             │
  │ 空搜索     │ 搜索无匹配结果                    │
  │ 无网络     │ 断网状态下操作                     │
  └────────────┴──────────────────────────────────┘

  AI视觉检查:
  - 统计每个功能模块提供的设计稿数量
  - 如果某个模块只有1张图(happy path),大概率缺少边界态
  
  典型反例:
  "消息列表页只提供了有消息的正常态截图"
  → 缺少: 空状态(没有任何消息)/加载中/消息加载失败

  建议:
  每个含数据列表的页面至少应包含:
  ✅ 有数据正常态 (主态, 1~3张)
  ✅ 空数据状态 (1张)
  ✅ 加载中状态 (1张)
  ✅ 加载失败状态 (1张,可选)
```

### IMG-STATE 组 — 状态覆盖（核心! 来自边界值分析）

#### IMG-STATE-01: 空数据/缺省态缺失
```yaml
规则ID: IMG-STATE-01
名称: "列表/表格/卡片区域的无数据(empty)状态设计缺失"
方法来源: 边界值分析法 (等价类: 空集 = 特殊等价类)
严重程度: CRITICAL

边界值视角:
  数据量 N 的等价类划分:
  N = 0  → 空状态 (必须设计!)
  N = 1  → 单条目状态
  N = 2~5 → 少量数据
  N > 分页阈值 → 多页数据

  空状态设计应包含:
  - 空状态插图/图标
  - 友好的文字说明 (为什么是空的?)
  - 引导操作的按钮/链接 ("去添加第一个XXX")

  AI视觉检查:
  检查所有列表型组件是否有对应的空态设计稿
  如果发现任何列表只有"有数据"的状态 → 报 CRITICAL
```

#### IMG-STATE-02: 加载中/骨架屏缺失
```yaml
规则ID: IMG-STATE-02
名称: "页面或数据的加载中状态(skeleton screen / spinner)缺失"
方法来源: 边界值分析法
严重程度: CRITICAL

检查要点:
  - 首屏加载: 有没有骨架屏(Skeleton)或 Loading 动画?
  - 下拉刷新: 有没有刷新中的状态?
  - 异步数据加载: 展示区有没有 placeholder?
  - 按钮点击后: 有没有 loading/disable 状态?

  推荐方案优先级:
  1. 骨架屏 Skeleton Screen (最佳体验)
  2. Spinner + 半透明遮罩 (通用方案)
  3. 按钮 loading 态 (局部loading)
```

#### IMG-STATE-03: 错误/异常态设计缺失
```yaml
规则ID: IMG-STATE-03
名称: "操作失败/系统错误的UI反馈设计缺失"
方法来源: 错误推测法
严重程度: CRITICAL

需要设计的错误态 (错误推测Checklist):
  ┌────────────────────────────────────────────┐
  │ 表单提交失败                                │
  │ ☐ 校验错误(前端): 内联错误提示              │
  │ ☐ 业务规则违反: Toast/Alert提示            │
  │ ☐ 服务端异常: 全局错误页/弹窗              │
  ├────────────────────────────────────────────┤
  │ 数据请求失败                                │
  │ ☐ 网络断开: 离线提示+重试按钮              │
  │ ☐ 服务器500: 友好错误页                   │
  │ ☐ 404/403: 对应的提示页                   │
  │ ☐ 超时: 超时提示+重试                     │
  ├────────────────────────────────────────────┤
  │ 操作失败                                    │
  │ ☐ 支付失败: 失败原因+重试/更换方式        │
  │ ☐ 上传失败: 原因+重新上传                 │
  │ ☐ 权限不足: 提示+申请权限入口             │
  └────────────────────────────────────────────┘

  AI视觉检查:
  逐个错误场景核对是否有对应的UI设计稿
```

### IMG-A11Y 组 — 无障碍规则

#### IMG-A11Y-01: 色彩对比度不足
```yaml
规则ID: IMG-A11Y-01
名称: "文字与背景的颜色对比度不符合WCAG AA标准"
方法来源: 错误推测法
严重程度: BLOCKER

WCAG AA 标准:
  - 普通文字: 对比度 ≥ 4.5:1
  - 大号文字(18pt+/14pt bold): 对比度 ≥ 3:1
  - 非文字元素(图标/形状): 对比度 ≥ 3:1

  常见违规模式 (AI可检测):
  - 浅灰色文字 (#999, #AAA) 在白色背景上
  - 浅色文字在渐变背景上
  - 禁用状态的文字对比度过低
  - 占位符(placeholder) 文字太浅
  - 辅助信息/说明文字颜色过浅

  检测方式:
  AI分析设计稿中的文字元素,计算前景色与背景色的对比度,
  不满足 WCAG AA 的标注为 BLOCKER。
  
  工具参考: WebAIM Contrast Checker, Stark Plugin(Figma)
```

#### IMG-A11Y-03: 触控目标尺寸过小
```yaml
规则ID: IMG-A11Y-03
名称: "可点击/可触控元素的尺寸小于WCAG 2.5.5标准"
方法来源: 边界值分析法
严重程度: CRITICAL

WCAG 2.5.5 Target Size (Minimum):
  - 触控目标尺寸 ≥ 44×44 CSS pixels (推荐 48×48)
  - 例外: 行内链接/同等上下文中的小元素

  常见违规:
  - 图标按钮太小 (< 36px × 36px)
  - 链接文字行高不够 (touch target < 44px 高)
  - checkbox / radio 太小
  - 密集的操作图标栏 (如工具栏)

  AI视觉检测:
  识别所有可交互元素(button/icon/link/toggle),
  测量其最小包围盒尺寸,
  < 44×44px → 报 CRITICAL
```

### IMG-DATA 组 — 数据展示

#### IMG-DATA-01: 列表/表格缺少分页或加载更多
```yaml
规则ID: IMG-DATA-01
名称: "长列表/数据表格的分页(Pagination)或无限滚动(Infinite Scroll)设计缺失"
方法来源: 边界值分析法
严重程度: CRITICAL

检查逻辑:
  设计稿中如果出现数据列表/表格:
  - 是否展示了分页器组件? (页码/上一页下一页/跳转)
  - 是否设计了「加载更多」按钮?
  - 是否设计了「滚动到底部自动加载」?
  
  边界考虑:
  - 只有1页数据时的分页器显示/隐藏?
  - 到达最后一页时的状态?
  - 极端大量页数时(1000+页)如何处理?

  反例:
  "用户列表只展示了10条数据的表格,但没有分页设计"
  → 当用户量增长后,无法处理大数据量的浏览
```
